# Image preproduction workflow

图片预制作把文字故事转成可复用的视觉资产，再用于分镜图、首尾帧和视频生成。用户只要提示词时，输出计划与提示词；用户明确要求生成图片时，调用可用的内置 imagegen 能力。

## 何时使用

适合：

- 多镜头短片需要固定人物、服装和场景；
- 用户需要人物设定图、场景图、道具图或镜头首尾帧；
- 直接文生视频出现人物漂移或空间跳变；
- 用户希望先看视觉方向，再投入视频生成。

简单单镜头、抽象动态测试或已有完整参考素材时，可以跳过部分步骤。

## 三阶段生产链

### 阶段一：设计设定板

建立项目的视觉词典：

- 角色：正面、四分之三侧面、侧面、全身、关键表情；
- 服装：完整造型、材质、颜色、鞋、饰品；
- 道具：比例、磨损、颜色和使用方式；
- 场景：建立视角、平面关系、入口出口、主要光源；
- 风格：色板、对比度、质感和真实感规则。

优先分别生成清晰资产，不要把所有信息挤进一张复杂拼贴图。设定板用于概览时，可以制作网格；身份敏感的正式参考图仍应保留独立文件。

### 阶段二：静态分镜与关键帧

先写镜头表，再为每镜选择：

- 单独分镜图；
- 视频首帧；
- 必要时的视频尾帧；
- 仅用于构图、灯光或动作的参考图。

每张静态图只表现一个可拍摄瞬间。遵循 [../references/storyboard-grammar.md](../references/storyboard-grammar.md)。

### 阶段三：从图片进入视频

1. 选择通过检查的角色、场景和首帧资产。
2. 给每张图片稳定编号，例如 @人物1、@场景1、@首帧03。
3. 在视频 Prompt 中写明每张图片负责什么，以及不负责什么。
4. 加入 Continuity Lock 与本镜 Shot Delta。
5. 只描述从首帧开始的动作、主运镜和结束状态。
6. 视频成功后保存尾帧、Prompt 和设置，用于下一镜接力。

## 使用内置 imagegen

用户明确要求实际生成或编辑图片时：

1. 默认使用内置 imagegen，不要求用户提供 API Key。
2. 新图生成：为每个不同资产使用独立 Prompt 和独立生成调用。
3. 参考生成：明确每张输入图片的职责。
4. 编辑本地图片：先查看图片，再提交编辑；不要凭文件名猜内容。
5. 编辑时使用“只修改 / 必须保持”结构，非破坏性保存新版本。
6. 每张图生成后检查主体、身份、构图、文字、约束和用途。
7. 一次只修正一个主要问题。
8. 项目要使用的最终图片应保存进项目目录，并报告路径；仅供讨论的预览图可以直接展示。

如果内置 imagegen 不可用，说明可选的显式 CLI/API 路径及其前置条件，不要私自切换。

## 图片 Prompt 结构

    【用途】角色参考图 / 场景参考图 / 分镜图 / 首帧 / 尾帧
    【场景】空间、时间、天气和故事线索
    【主体】身份、外貌、服装、姿势、视线和道具
    【构图】景别、角度、画幅、主体位置和留白
    【灯光】可见光源、方向、软硬、对比和色温
    【色彩与质感】主色、辅助色、真实感和材料细节
    【参考素材】每张图片的明确职责
    【Continuity Lock】不可变化的视觉事实
    【Shot Delta】本图允许发生的变化
    【文字】精确文字或明确无文字
    【避免】最可能出现的失败

## 编辑 Prompt 结构

    【只修改】
    <一个明确的视觉变化>

    【必须保持】
    <人物身份、面部、发型、姿势、身体比例、构图、摄影机角度、
    背景布局、道具、光向、画幅等不允许变化的内容>

    【避免】
    <与本次编辑最相关的失败>

## 文件与版本

建议命名：

    character_01_identity_v01.png
    character_01_wardrobe_v01.png
    location_01_establishing_v01.png
    shot_003_first_frame_v01.png
    shot_003_last_frame_v01.png

保留成功版本，不直接覆盖。资产清单记录：文件名、用途、Prompt、参考来源、版本、通过/待修改和连续性备注。

## 交付内容

图片预制作任务应返回：

1. 资产清单与生成顺序；
2. 每项资产的最终 Prompt；
3. Continuity Lock；
4. 已生成图片的预览和路径；
5. 未通过项与最小修复建议；
6. 图片到视频的引用映射。
